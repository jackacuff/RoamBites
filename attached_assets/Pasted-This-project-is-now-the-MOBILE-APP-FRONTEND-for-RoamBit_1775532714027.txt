This project is now the MOBILE APP FRONTEND for RoamBites.

IMPORTANT:
Do NOT convert or destroy the existing website architecture. Do NOT turn this into just a wrapped webview. Do NOT rebuild the backend from scratch unless absolutely necessary.

The goal is to create a native-feeling iOS app version of RoamBites that stays connected to the same backend, database, auth system, and business logic as the existing web app.

The website and mobile app should remain connected through shared data and backend logic, but this mobile project should have its own frontend, navigation, layouts, and mobile-specific UX.

-----------------------------------
CORE GOAL
-----------------------------------

Build an App Store-ready iOS mobile app version of RoamBites using the best mobile-native framework Replit supports, preferably:
- Expo
- React Native

Reuse the existing RoamBites backend and data structure where possible.

This app should feel like a true mobile app, not a website inside an app shell.

-----------------------------------
DO NOT
-----------------------------------

- Do NOT make this just a web wrapper
- Do NOT break the existing shared backend
- Do NOT remove current user roles or business logic
- Do NOT create a disconnected second system unless necessary
- Do NOT overcomplicate the first mobile version

-----------------------------------
SHARED SYSTEMS THAT SHOULD STAY CONNECTED
-----------------------------------

The mobile app should use the same:
- user accounts
- authentication
- food truck data
- event data
- booking data
- favorites
- reviews
- organizer data
- vendor data
- admin/superadmin logic if practical
- subscription and monetization structure where relevant

If backend APIs need cleanup or new endpoints for mobile consumption, improve them carefully without breaking the web version.

-----------------------------------
MOBILE APP EXPERIENCE
-----------------------------------

The mobile app should be optimized for iPhone first.

Use mobile-native UX patterns including:
- bottom tab navigation
- stack navigation for detail pages
- native-feeling buttons and spacing
- loading states
- error states
- pull to refresh where appropriate
- mobile-friendly map behavior
- native share integration where possible
- proper permission prompts for location
- image upload behavior that makes sense on mobile
- smooth transitions between screens

-----------------------------------
MAIN APP SECTIONS
-----------------------------------

Build the mobile app around these main areas:

1. Home
- Hero/home screen adapted for mobile
- easy access to:
  - Browse Trucks
  - Live Map
  - Events
- surface open trucks and featured events cleanly

2. Live Map
- map of open/live food trucks
- user location dot if permission granted
- easy access to truck details from pins/cards
- fast and clean mobile map experience

3. Trucks / Browse
- browse all trucks
- filter/search
- truck detail pages
- favorites
- reviews
- see menus, schedules, specials, and branding

4. Events
- browse events
- featured events
- event detail pages
- food truck lineup
- event map if implemented
- event organizer flows if practical for mobile

5. Account
Role-aware account area

For customer:
- profile
- favorites
- reviews
- notifications

For vendor:
- vendor dashboard
- truck management
- schedule
- live location
- bookings
- event opportunities
- social/share tools if practical

For organizer:
- organizer dashboard
- create/manage events
- manage spots
- reservations
- payments if practical

-----------------------------------
